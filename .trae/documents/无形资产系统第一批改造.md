# 无形资产管理系统第一批改造方案

## Context（为什么改）

用户基于完整的无形资产管理功能点清单（6 大模块、20+ 子功能）要求改造现有系统。现有 13 个页面只覆盖了部分功能，存在三类缺口：
1. **资产档案维度不全**——asset-manage 只支持专利/软著/商标 3 类，缺少域名、土地使用权、特许经营权、非专利技术、客户关系、品牌价值等类型；缺少取得方式、权利归属、发明人、附件等关键字段
2. **没有处置与核销**——资产退役（出售/报废/失效/注销）无入口，退役资产无处归档
3. **年费/续展预警薄弱**——archive 页只有一个简单的年费提醒，没有多级预警、没有续展管理
4. **没有合同管理**——知识产权许可/转让/质押合同完全缺失

目标：补齐这 4 项，让"一物一码"档案完整、资产全生命周期闭环、风控预警可执行、合同履约可跟踪。坚持"看得见摸得找"的产品主线——所有新功能都要让客户能在一个地方看全一个资产的一生。

## 改造范围（4 项，第一批）

### 项 1：资产档案完善（asset-manage.html + asset-data.js）

**数据层 asset-data.js 扩展字段**：
- `category`：资产大类（知识产权类/权利特许类/技术秘密类/市场客户类/品牌价值类）
- `acquireMethod`：取得方式（外购/自主研发/投资入股/捐赠/内部调拨）
- `ownerShip`：权利归属（本公司/子公司/个人/共有）
- `inventor`：发明人/作者
- `attachments`：附件数组 `[{name, type, uploadDate, size}]`（文件名模拟，不真传文件）
- `legalStatus`：法律状态细化（申请中/审查中/已授权/有效中/失效/质押冻结/诉讼中）

**表单层 asset-manage.html**：
- 资产类型下拉扩展为 10 类（发明专利/实用新型/外观设计/商标/软件著作权/域名/土地使用权/特许经营权/非专利技术/客户关系/品牌价值），选中后自动带默认摊销年限
- 新增"取得方式"下拉、"权利归属"下拉、"发明人"输入框
- 新增"附件管理"区：文件名列表 + 模拟上传按钮（添加文件名+类型+日期），支持删除
- 法律状态从 archive 的简单"有效中/审查中/已失效"扩展为 7 态（加质押冻结/诉讼中/申请中）
- 表单分组：基本信息 / 摊销信息 / 价值信息 / 权属与发明人 / 附件管理 / 标签

### 项 2：处置与核销（新建 disposal.html）

**数据层**：
- 新增 `disposal` 字段：`{type, date, reason, operator, proceeds, approvedBy}`
- `status` 增加"已处置"态
- 新增 `ASSET_DISPOSALS` localStorage 键，记录处置历史（资产ID/类型/日期/原因/操作人/处置收入/审批人）

**页面层 disposal.html**：
- 上半区：有效资产列表（可勾选 → 批量发起处置）
- 下半区：处置台账（已处置资产历史记录，含处置类型/日期/原因/收入/审批人）
- 发起处置弹窗：选择处置类型（出售/报废/失效/注销）、填原因、处置收入、审批人 → 确认后资产状态变为"已处置"、写入处置台账

### 项 3：年费与续展预警（新建 fee-renewal.html）

**数据层**：
- 扩展 `feeRenewal` 字段：`{type, amount, dueDate, paidDate, alertLevel, note}`（type: 年费/续展费/维保费）
- `alertLevel` 自动计算：距到期 >90天=正常 / 30-90天=提醒(黄) / <30天=紧急(红) / 已过期=过期

**页面层 fee-renewal.html**：
- 顶部三个统计：正常/待缴(黄)/紧急(红)/已过期
- 列表：筛选全部/待缴/紧急/已过期，每行显示资产名/费用类型/金额/到期日/剩余天数/状态
- 操作：标记已缴费（填缴费日期+凭证号）→ 状态变为正常、到期日顺延一个周期

### 项 4：合同管理（新建 contract.html）

**数据层**：
- 新增 `ASSET_CONTRACTS` localStorage 键（独立于资产数据，但关联 assetId）
- 合同结构：`{id, contractNo, type, assetIds[], counterparty, amount, signDate, startDate, endDate, paymentNodes[], status, files[]}`
- type: 许可合同/转让合同/质押合同
- paymentNodes: `[{name, amount, dueDate, paidDate, status}]`

**页面层 contract.html**：
- 列表：合同编号/类型/关联资产/对方/金额/状态/履约进度
- 新增/编辑弹窗：合同基本信息 + 关联资产（多选）+ 收付款节点（动态添加）
- 详情：合同信息 + 收付款节点进度条 + 附件列表

### 侧边栏整合（index.html）

把现有扁平菜单重组为 6 个分组（对应 6 大模块），第一批只填入有页面的组：
- **① 档案与台账**：资产档案维护、证书与进度、资产盘点、价值台账、费用台账
- **② 全生命周期**：申报进度跟踪、研发账变资产、**处置与核销**（新）
- **③ 权利维护**：**年费与续展预警**（新）
- **④ 价值与财务**：每月摊销与省税、估值与投资回报
- **⑤ 运营与合规**：申报与审计助手、**合同管理**（新）
- **⑥ 统计与决策**：资产全景图（home）

## 验证方式

1. **node 单元测试**：asset-data.js 字段扩展 + 新数据集 CRUD + 派生计算（alertLevel 自动算）
2. **浏览器端到端**：
   - asset-manage 新增一个"域名"类型资产，填取得方式/权利归属/发明人/附件 → 保存 → archive 页能看到
   - disposal 勾选有效资产 → 发起报废 → 资产状态变"已处置" → 处置台账有记录
   - fee-renewal 看到紧急(红)项 → 标记已缴费 → 状态变正常、到期日顺延
   - contract 新增许可合同 → 关联多个资产 → 添加收付款节点 → 详情看进度

## 不做（第一批排除）

- 法律状态对接官方数据库（国家知识产权局 API）——需真实接口，原型不接
- 侵权监控集成外部舆情——同上
- 财务系统对接（SAP/用友/金蝶）——需真实 ERP 接口
- 减值测试模型——第二批
- 数据隐私 GDPR 合规检查——第二批
- 自定义报表导出 Excel/PDF——第二批
